# Как мы работаем с кодом

Короткая версия: **ветка от `dev` → маленький PR → метка `ready` → слияние ботом.** Пошаговые команды — в [docs/git-guide.md](docs/git-guide.md).

## 1. Ветки

| Ветка | Что это | Кто пушит | Как попадает дальше |
|---|---|---|---|
| `main` | Стабильная версия. Каждый сабмит на платформу — тег на `main` | никто напрямую | PR «релиз» из `dev`, сливает **дежурный дня** |
| `dev` | Интеграция, ветка по умолчанию | никто напрямую | PR из веток задач, сливает **бот** |
| `team/<имя>` | Личная ветка: твой `START_HERE.md` и заметки | только владелец | **никогда не сливается** в `dev` |
| `<роль>/<задача>` | Ветка задачи, живёт 0.5–1 день | автор | PR в `dev`, после слияния удаляется автоматически |

Роли в именах веток: `captain`, `agent`, `ml`, `research`, `qa`. Примеры: `agent/llm-hypotheses`, `ml/catboost`, `qa/harness`.

> ⚠️ Не открывай PR из `team/<имя>` в `dev`: GitHub удалит личную ветку после слияния, а `START_HERE.md` попадёт в общий код.

## 2. Права и ревью

**Команда плоская** ([ADR 0009](docs/decisions/0009-flat-team.md)): у всех одинаковые права, нет человека, которого нужно просить «слей мой PR». PR сливает **бот**. Вместо иерархии — предохранители:
1. git-хук `pre-push` (ставит `scripts/install_hooks.py`) — не даёт пушить в `main`/`dev` и делать force push;
2. запреты в `.claude/settings.json` — Claude тоже не сможет;
3. сторож `guard.yml` отключён капитаном 21.10 (включить обратно: `gh workflow enable guard.yml`);
4. **бот слияний** (`integrate.yml`) — сливает только то, что одобрено и прошло CI;
5. договорённости ниже. Нарушил случайно — сразу напиши в чат, это нормально.

| Что меняет PR | Одобрений | Кто сливает |
|---|---|---|
| Обычный код и документация | **1**, от любого коллеги | бот |
| **`interfaces/`, `.github/`, `.claude/`, `.githooks/`, `solution.py`** — то, от чего зависят все | **2**, от любых коллег; автор сам зовёт ревьюерами тех, кого это касается | бот |
| `dev → main` (релиз под сабмит) | 1, от qa | **дежурный дня** ([team-process.md](docs/team-process.md)) |

Кого бот просит в ревьюеры по умолчанию (одобрить может любой коллега, это лишь подсказка, чтобы не выбирать):

| Автор | Просим |
|---|---|
| agent | ml |
| ml | research |
| research | ml |
| qa | agent |
| captain | qa |

Кто какой папкой владеет — [.github/CODEOWNERS](.github/CODEOWNERS): это карта ответственности («с кем советоваться»), а не разрешение или запрет.

## 3. Правила PR

- **Маленький PR лучше большого.** Ориентир: до 300 строк, одна задача.
- Перед PR: `/pre-pr` в Claude Code или вручную `uv run ruff check . && uv run pytest`.
- В описании — по шаблону: что, зачем, как проверить, затронуты ли контракты.
- CI должен быть зелёным. Красный CI — не сливаем, даже «на минутку».
- **Слияние делает бот** (`integrate.yml`). Готов — поставь на PR метку `ready`. Раз в 30 минут бот проверяет: одобрений хватает, CI зелёный, конфликтов нет, ветка не отстала от `dev` — и сливает (Squash). Если что-то не так, пишет причину комментарием в PR. `hotfix` — слить сразу, `wait` — не сливать. Бот обновил твою ветку — сделай `git pull`.

## 4. Коммиты

Формат: `тип: что сделано` — по-русски, в повелительном наклонении.

| Тип | Когда |
|---|---|
| `feat:` | новая возможность (`feat: добавить CatBoost в реестр моделей`) |
| `fix:` | исправление ошибки |
| `test:` | тесты |
| `docs:` | документация |
| `refactor:` | переделка без изменения поведения |
| `chore:` | служебное: зависимости, CI, настройки |
| `exp:` | эксперимент (результат — в `docs/experiments.md`) |

## 5. Контракты (`interfaces/`)

`interfaces/` — договор между модулями. Его изменение ломает чужой код, поэтому:
1. перед изменением — `/sync-check` в Claude Code и сообщение в чат: «хочу поменять X, затронет Y»;
2. PR только с изменением контракта (без другой логики), `CONTRACT_VERSION` повышен, строка в `interfaces/CHANGELOG.md`;
3. ревью всех затронутых владельцев, **два одобрения**, сливает бот (`ready`);
4. мажорное изменение (переименование/удаление поля) — только на синке.

## 6. Ключи и секреты

- Ключи живут **только** в файле `.env` (он в `.gitignore`). Шаблон — `.env.example`.
- Никогда не вставляем ключ в код, чат, issue, PR, скриншоты и в разговор с Claude.
- Claude Code настроен не читать `.env` (запрет в `.claude/settings.json`).
- Ключ случайно попал в git или чат → **сразу** пиши капитану: ключ надо перевыпустить у организаторов. Удаление коммита не помогает — история уже ушла на GitHub.

## 7. Чужой код

- Чужой модуль меняем только после согласования с владельцем (CODEOWNERS). Нашёл баг — issue или сообщение владельцу.
- Хочешь взять чужие наработки из ветки — `git cherry-pick` или попроси автора открыть PR (см. git-guide, раздел «Забрать нужное из чужой ветки»).
- Застрял больше 30 минут — пиши в чат. Это правило, а не просьба.
