# Связка Claude: тимлид + разработчики

Черновик протокола. Правила git и ревью не меняются — [CONTRIBUTING.md](../CONTRIBUTING.md). Здесь только то, как несколько Claude работают вместе и не ломают друг другу `dev`.

## Роли

| Кто | Делает | Не делает |
|---|---|---|
| **Тимлид** (сессия капитана) | режет задачи, выдаёт бриф, проверяет diff и CI, зовёт ревьюеров | не пишет код задач, не правит чужие зоны |
| **Разработчик** (`agent`, `ml`, `research`, `qa`) | одна задача → одна ветка → один PR в своей зоне ([CODEOWNERS](../.github/CODEOWNERS)) | не трогает `interfaces/`, `.github/`, `.claude/`, `solution.py` без согласования с тимлидом |
| **Человек** | ставит `ready`, одобряет PR, решает спорное | — |

## Правила (каждое закрывает конкретную причину поломок)

1. **Одна сессия = один worktree = одна ветка = один PR.** Два агента никогда не работают в одной папке.
2. **Зоны файлов не пересекаются.** В брифе перечислены файлы, которые можно менять. Нужно выйти за список — стоп и вопрос тимлиду.
3. **Ветка всегда от свежего `dev`.** Перед стартом `git fetch && git switch -c <роль>/<задача> origin/dev`. Перед PR — подтянуть `dev`, иначе бот всё равно вернёт PR на обновление.
4. **«Готово» = зелёный `/pre-pr` + зелёный CI**, а не слова агента. Тимлид сверяет `gh pr checks <N>` и читает diff сам.
5. **Не больше 2 открытых PR на агента.** Следующая задача — после слияния предыдущей.
6. **PR до 300 строк.** Больше — режем на части.
7. **Контракты (`interfaces/`) меняет только тимлид**, отдельным PR по процессу из CONTRIBUTING §5.
8. **Слился PR — worktree удаляем сразу** (`git worktree remove <путь>`). Висящие worktree — главный источник путаницы «где какая версия».
9. **Локальный `dev` всегда чистый.** Правки в основной папке — только через ветку: `autosync.sh` делает `git pull --ff-only` и молча перестаёт обновляться, если там есть локальные изменения.
10. **Откат вместо починки на ходу.** Сломал `dev` — `git revert` слитого PR, потом разбор.

## Бриф тимлида разработчику (шаблон)

```
Задача: <одна фраза> (issue #N)
Ветка: <роль>/<задача> от свежего origin/dev
Можно менять: <файлы/папки>
Нельзя: interfaces/, .github/, .claude/, solution.py, чужие зоны
Готово, когда: <проверяемый критерий>; uv run ruff check . && uv run pytest зелёные
Итог: PR в dev по шаблону, отчёт мне: ссылка на PR + что НЕ проверено
```

## Отчёт разработчика (шаблон)

```
PR: <ссылка>
Что сделано: ...
Как проверил: <команда + результат>
Что не проверил / риски: ...
Выходил за зону: да/нет (если да — что и почему)
```

## Как запускать

- **Субагенты в одной сессии** (проще, общий контекст): роли в `.claude/agents/`, тимлид вызывает их через Agent. Подходит для ревью и написания тестов.
- **Отдельные сессии в worktree** (изоляция): тимлид стартует сессию на каждую задачу и пишет ей через SendMessage. Подходит для кода, который идёт в PR.

Начинать с тимлид + 1 разработчик на 2–3 задачи; если `dev` не ломался — добавлять остальных.
