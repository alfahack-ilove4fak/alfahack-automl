# Релиз: dev → main и тег сабмита

Сабмитим **только из тега на `main`**. Так у каждой строки в [журнале сабмитов](submissions.md) есть точный коммит, и любой сабмит можно воспроизвести. Всё делает один скрипт — `scripts/release.py`; без `--yes` он только проверяет и печатает план, ничего не меняя.

## Когда
Окно интеграции 2 (18:30) → решение «сабмитим ли сегодня» → релиз → сабмит в 19:00 ([ритм дня](team-process.md)). Лимит платформы — 3 сабмита в день, сброс в 00:00 МСК: тег `N` считается по московской дате.

## Шаг 1. PR «dev → main» (стадия `pr`)
Вы на актуальном `dev` (`git switch dev && git pull`):

```
uv run python scripts/release.py          # проверки + план, ничего не создаёт
uv run python scripts/release.py --yes --reviewer <ник qa>
```

Скрипт проверяет: чистое дерево, `HEAD == origin/dev`, зелёный CI именно для этого коммита, `ruff`, `pytest`, что в `dev` есть что релизить. Затем собирает контрольный zip и открывает PR «release: dev → main» с заметками (список слитых PR).

Сливаем кнопкой **Create a merge commit** — не squash: иначе `main` разойдётся с `dev`.

## Шаг 2. Тег (стадия `tag`)
После слияния — на актуальном `main` (`git switch main && git pull`):

```
uv run python scripts/release.py --yes
```

Проверки те же + «коммит ещё без тега» + лимит 3 сабмита/день + `scripts/pre_submit.py` (прогон архива как на платформе). Затем: архив `dist/submit-ГГГГММДД-N.zip`, аннотированный тег `submit-ГГГГММДД-N`, `git push origin <тег>`, GitHub Release с zip, sha256 и заметками.

## Шаг 3. Сабмит и журнал
Загрузите `dist/<тег>.zip` на платформу и добавьте строку в [docs/submissions.md](submissions.md): тег, что нового, локальный скор, public score, кто отправил.

## Флаги
| Флаг | Зачем |
|---|---|
| `--stage pr\|tag` | принудительно выбрать шаг (по умолчанию: `HEAD == origin/main` → `tag`, иначе `pr`) |
| `--skip-tests` | не гонять pytest локально, если CI зелёный |
| `--skip-pre-submit` | не запускать `pre_submit.py` (долго; только если уже гоняли) |
| `--pre-submit-minutes N` | бюджет `pre_submit.py` на задачу |
| `--allow-over-limit` | разрешить тег №4+ за день (платформа его не примет — для черновика) |
| `--reviewer <ник>` | ревьюер PR «dev → main» |

## Если что-то пошло не так
- **«нет прогона ci для этого коммита»** — подождите или запустите workflow `ci` вручную.
- **Тег создан, GitHub Release — нет** — тег уже на месте, release можно создать вручную: `gh release create <тег> dist/<тег>.zip`.
- **Тег поставили зря** — не удаляйте молча: напишите в чат; удаление тега — `git push --delete origin <тег>` только по решению капитана.
- **`main` и `dev` разошлись** (кто-то слил squash-ом) — не форсируйте: откройте issue, разберёт капитан.

Автотесты скрипта — `tests/unit/test_release.py` (без сети, git и gh).
