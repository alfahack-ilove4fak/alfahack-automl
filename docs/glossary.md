## Про задачу

| Термин | Простыми словами |
|---|---|
| **ML (машинное обучение)** | Программа сама находит закономерности в примерах и потом угадывает ответ для новых данных. |
| **Табличные данные** | Данные в виде таблицы (CSV): строка — объект (здание, сетевое соединение), столбец — его свойство. |
| **Признак (feature)** | Один столбец-свойство, по которому модель угадывает ответ: площадь здания, длительность соединения. |
| **Таргет (target)** | Столбец, который надо предсказать: энергопотребление `site_eui`, тип атаки `attack_cat`. |
| **train / test** | `train.csv` — примеры с ответами (на них учимся); `test.csv` — без ответов (их надо предсказать). |
| **Сабмит (submission)** | Файл `submission.csv` с нашими ответами для `test.csv`. Отправляем на платформу. |
| **Регрессия** | Предсказываем число (энергопотребление). |
| **Классификация** | Предсказываем категорию. Бинарная — из двух вариантов, многоклассовая — из многих (10 типов атак). |
| **Метрика** | Число, которым меряют качество ответов. Бывает «чем меньше, тем лучше» (RMSE) и «чем больше, тем лучше» (F1). |
| **RMSE** | Средняя ошибка в единицах таргета (корень из среднего квадрата ошибок). Меньше — лучше. Сильно наказывает за большие промахи. |
| **Macro F1** | Среднее качество по всем классам с одинаковым весом. Хорошо, если модель находит и редкие классы, а не только частые. |
| **Дисбаланс классов** | Одних классов много, других — единицы. Модель склонна «забивать» на редкие. |
| **Бейзлайн (baseline)** | Простое решение-точка отсчёта. У организаторов свой бейзлайн: если мы не лучше — 0 баллов. |
| **Public / private лидерборд** | Public — оценка на двух известных задачах, видна сразу. Private — на двух скрытых, решает итог. |

## Про модели и проверку

| Термин | Простыми словами |
|---|---|
| **Модель** | Алгоритм, который учится на train и выдаёт предсказания. |
| **Градиентный бустинг** | Много маленьких деревьев решений, каждое исправляет ошибки предыдущих. Лучший выбор для таблиц. Библиотеки: LightGBM, CatBoost, XGBoost. |
| **Гиперпараметры** | «Ручки» модели, которые задаём до обучения: число деревьев, скорость обучения. |
| **Переобучение** | Модель «зазубрила» train и плохо работает на новых данных. |
| **Валидация** | Проверка качества на данных, которые модель не видела при обучении. |
| **Кросс-валидация (CV)** | Делим train на 5 частей, 5 раз учимся на четырёх и проверяем на пятой. Среднее — честная оценка, разброс — мера шума. |
| **OOF (out-of-fold)** | Предсказания кросс-валидации для каждого объекта train — от модели, которая его не видела. Нужны для ансамблей. |
| **Ранняя остановка** | Прекращаем добавлять деревья, когда качество на валидации перестаёт расти. |
| **Утечка (leakage)** | В признаках «подсмотрен» ответ. CV выглядит отлично, а на тесте провал. |
| **Ансамбль** | Смешиваем предсказания нескольких моделей — обычно точнее любой одной. |
| **Препроцессинг** | Подготовка данных: заполнение пропусков, кодирование категорий, преобразования. |
| **Feature engineering** | Придумываем новые признаки из старых: «возраст здания» = год наблюдения − год постройки. |

## Про агента

| Термин | Простыми словами |
|---|---|
| **AutoML** | Автоматический перебор моделей и настроек по заданному сценарию. Не думает, *почему* модель ошибается. |
| **LLM** | Большая языковая модель (у нас — Qwen). Читает и пишет текст и код. |
| **AI-агент** | Программа, где LLM сама решает, что делать дальше: пишет код, запускает, смотрит результат, меняет план. |
| **AutoResearch** | Цикл «гипотеза → эксперимент → оценка → решение», который агент крутит сам. |
| **Гипотеза** | Предположение, которое может улучшить результат: «добавить признак X», «взять CatBoost». |
| **Playbook** | Наш список проверенных универсальных гипотез — агент берёт их, когда LLM недоступна. |
| **Промпт** | Текст-инструкция, который отправляем LLM. |
| **Токены** | Кусочки текста, за которые платим LLM. ~1 токен ≈ 3–4 символа. |
| **Песочница** | Отдельный процесс с ограничениями, где выполняется код, написанный LLM, — чтобы он не уронил агента. |
| **Контракт** | Договор между модулями: какие данные и в каком виде передаются (`interfaces/`). |
| **Заглушка (stub)** | «Фальшивая» реализация чужого модуля, чтобы работать параллельно, не дожидаясь коллегу. |
| **Харнесс** | Наш «локальный лидерборд»: прогоняет агента на задачах с известными ответами и считает баллы. |

## Про инструменты

| Термин | Простыми словами |
|---|---|
| **Git / ветка / коммит** | Git хранит историю кода. Коммит — сохранённая точка. Ветка — параллельная линия работы. |
| **PR (Pull Request)** | Запрос «влейте мою ветку в общую». Там проходит ревью и CI. |
| **Ревью** | Коллега читает твой код до слияния и ищет ошибки. |
| **CI** | Автоматическая проверка на GitHub: при каждом PR запускаются линтер и тесты. Зелёный — можно сливать. |
| **uv** | Менеджер Python и библиотек: `uv sync` ставит всё нужное, `uv run` запускает в окружении проекта. |
| **`.env`** | Локальный файл с секретами (ключ LLM). Никогда не коммитится. |
| **Claude Code** | ИИ-помощник в терминале: читает проект, пишет код, запускает тесты. У нас настроен под роли (SETUP_CLAUDE.md). |
| **MCP** | Способ подключить к Claude внешние инструменты: актуальную документацию библиотек, GitHub. |
| **Скилл / слэш-команда / сабагент** | Готовые «умения» Claude: `/next-task` — команда; скилл — инструкция под тип работы; сабагент — отдельный помощник (например, ревьюер). |
