## Что изменилось в стенде

До v2 стенд считал **cv** в обычной KFold/StratifiedKFold. Агент после #175/#176 считает CV в схеме `choose_validation` (время / группы дубликатов / kfold — ADR 0013) и принимает гипотезу по `agent.acceptance.accept` (попарно по фолдам, t ≥ 2). Значит, стенд ранжировал не то, что агент реально принимает.

Теперь стенд делает как агент:
- схема CV выбирается **один раз на задачу** — `choose_validation` по train-части, отложенная часть в роли test — и одна у бейзлайна и всех гипотез;
- на каждую гипотезу — решение агента **accepted** (`accept` против бейзлайна);
- в конце — сводка: `wins` (честно лучше бейзлайна), `mean_rel_gain` (средний честный выигрыш в долях бейзлайна), `accepted`, `accepted_and_win` (принял по делу). Несколько прогонов сводятся `--from-csv`.

**honest** — как в v1.2: `run_experiment` + `fit_predict_final` на train-части, метрика на отложенной части (последний период по времени или фолд групп дубликатов), отложенная часть не участвует даже в ранней остановке.

## Выводы

1. **C0: `balanced_proba_weights` подтверждена** — честно лучше на всех 3 задачах с дисбалансом (медиана +15.5%), агент принимает её на всех трёх. Остаётся №1.
2. **Одно ложное принятие из 30 принятий (167 пар «гипотеза × задача»)** — `xgboost_balanced_proba_weights` на payments: CV 0.215 против 0.104 у бейзлайна, честно F1 0.132 против 0.180 (time-CV на редком классе шумит). Против `balanced_proba_weights` (CV 0.271) она не проходит, поэтому стоит строго после неё — закреплено тестом `test_xgboost_proba_weights_after_lightgbm_one`. Остальные принятия — по делу.
3. **Лучшие новые — XGBoost-комбинации:** `xgboost_log_target` честно −11.7% RMSE на public/regression (43.6 против 49.4) и −18% MAPE на claims; `xgboost` 6/10, на regression −8.8%. На regression агент их всё равно не примет: time-CV по годам шумит (±5 RMSE), t < 2. Это главный неиспользованный резерв public/regression.
4. **`lgbm_extra_trees` — 7/10 честно, 0 принятий** (как и в v1): CV систематически против неё. Аргумент за честную отложенную часть в цикле или за другое правило принятия для «регуляризующих» гипотез — к @n0h4ndy.
5. **«LightGBM по умолчанию», `catboost`, `hist_gb` — не универсальные улучшения** (медиана ≤ 0, на regression честно −15…−30%), но страховка и разнообразие для ансамбля (#32): в конце playbook, агент берёт их только там, где они лучше по его правилу (на 10 задачах — только по делу).
6. **`lgbm_fine_bins` — худшая** (3/10, медиана −0.2%), но ни разу не принята зря — оставлена последней.
7. **#206 одним playbook не закрыть.** На задачах #206 честно лучше бейзлайна есть гипотеза — diabetes: `lgbm_extra_trees` +6.2%, `lgbm_slow_regularized` +4.6%; network: `lgbm_slow_regularized` +2.0% ✓ (принимается); sales: `log_target` +7.4% (теперь в бейзлайне — #219), — но на diabetes агент не принимает ни одну: на 250 строках разброс фолдов больше выигрыша. Это вход для @marenkov17 (#206) и @n0h4ndy (`accept`): точнее сравнивать на малых данных (повторная CV), порог не снижая.
