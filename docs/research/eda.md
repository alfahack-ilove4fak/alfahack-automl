# EDA публичных задач — что важно для агента (R-L1-1)

Автор: roma (@Richi-Marqez) · 21.10.2026 · Воспроизвести: `research/notebooks/01_eda_checks.ipynb`.

**Главное.** На обеих задачах обычная перемешанная кросс-валидация **оптимистична**: строки train связаны между собой сильнее, чем train связан с test. В регрессии test — следующий год (разница ~5 RMSE). В классификации почти половина train — дубликаты (разница ~0.02 Macro F1). Агент должен сам находить такие ситуации на любой задаче — список проверок в конце.

Цифры CV — быстрый LightGBM (`learning_rate=0.1`, `num_leaves=63`, ранняя остановка 100, 5 фолдов, seed 42). Это разведка; честное сравнение схем валидации и сверка с public — задача R-L2-1.

## 1. Регрессия — энергопотребление зданий (`site_eui`, RMSE)

| Что | Факт | Почему важно |
|---|---|---|
| Таргет | 1–993, медиана 77, 99% < 306; skew **4.76**, после `log1p` −1.16; нулей нет; 2.3% строк > Q3+3·IQR | длинный правый хвост; RMSE его сильно наказывает → гипотеза `log_target` (проверять: log смещает среднее, на RMSE может и проиграть) |
| Время | train — годы `Year_Factor` 1–5, **test — только год 6** | test целиком «из будущего» → валидировать на последнем году train |
| Повторы зданий | ключ «здание» (штат, класс, тип, площадь, год постройки, высота) → 42 531 здание на 53 308 строк; **35% строк** — здания, встречающиеся несколько раз | разброс таргета внутри здания (медиана std 6.8) в 9 раз меньше общего (58.7) — модель «узнаёт» здание из соседнего фолда |
| Здания test в train | только **38%** зданий test есть в train | в случайном KFold доля «знакомых» зданий выше, чем будет на test |
| Пропуски | `days_with_fog` 62%, направление/скорость ветра ~50%, `energy_star_rating` 42%, `year_built` 3% | бустинг терпит NaN; флаг «пропуск» — кандидат в playbook |
| Константы | нет | — |

⚠️ Ключ «здание» подобран руками (в данных нет id здания); до 12 строк на ключ при 5 годах — значит, иногда разные здания склеиваются. Для агента нужен автоматический способ (см. проверку 3).

**Схемы валидации:**

| Схема | RMSE (↓) | Комментарий |
|---|---|---|
| KFold(5, shuffle) — как сейчас в `ml/experiment.py` | **41.95 ± 1.17** | совпадает с бейзлайном в журнале (41.81) |
| GroupKFold(5) по зданию | 43.89 ± 1.38 | убирает утечку через здание |
| Время: годы 1–4 → год 5 | 46.92 | ближе всего к постановке test |
| Время: expanding (≤k → k+1, k = 2..4) | 48.93 ± 4.77 | ранние годы малы (2 117 строк в году 1) |

Вывод: случайный KFold занижает ошибку примерно на 5 RMSE (~12%). Опаснее другое: гипотезы, которые «запоминают» здания (глубокие деревья, мелкие листья), на KFold выигрывают, а на test — нет. Порог шума 0.32 из журнала при таком смещении ничего не гарантирует.

## 2. Классификация — типы сетевых атак (`attack_cat`, Macro F1)

| Что | Факт | Почему важно |
|---|---|---|
| Дисбаланс | 10 классов; Normal 31.9% … Worms 0.07% (~60 строк); самый частый / самый редкий = **431×** | стратификация обязательна; 60 строк Worms → ~12 в фолде, F1 по нему шумный |
| Категории | `proto` 133 значения (3 редких < 10 строк), `service` 13, `state` 9; новые в test: `state` ∈ {ACC, CLO} — 3 строки | кодирование категорий обязано переживать новые значения; редкие — кандидаты в «other» |
| Константы | нет, квазиконстант (> 99% одно значение) тоже нет | — |
| Дубликаты | **44.8% строк** train входят в группы полных дубликатов по признакам (5 816 групп); Generic — 96% дубликатов, DoS 79%, Analysis 80%, Normal 8% | одинаковые строки попадают и в train, и в valid фолда |
| Конфликт меток | **16.9% строк** — дубликаты с разными метками (DoS/Exploits, Fuzzers/Normal, …) | неустранимая ошибка: по признакам эти классы не различить — потолок Macro F1 ниже 1 |
| Совпадение test с train | только **8.6%** строк test точно есть в train | внутри train дубликатов в 5 раз больше, чем между train и test → CV оптимистична |
| `id` | медиана id по классам почти одинакова | утечки через id не видно |

**Схемы валидации:**

| Схема | Macro F1 (↑) | Комментарий |
|---|---|---|
| KFold(5) без стратификации | 0.5509 ± 0.0110 | разброс почти вдвое больше |
| StratifiedKFold(5) — как сейчас | **0.5678 ± 0.0065** | |
| StratifiedGroupKFold(5), группа = дубликаты | 0.5497 ± 0.0080 | на ~0.018 ниже. ⚠️ Чувствительна к разбиению: черновой прогон с другим перемешиванием групп дал 0.5563 ± 0.0188 (группы Generic крупные) |

Вывод: стратификация точно нужна (разброс меньше в 1.7 раза). Группировка дубликатов снижает оценку на 0.01–0.02 — это сопоставимо с выигрышем типичной гипотезы (playbook дал +0.037), так что часть «улучшений» может быть запоминанием дубликатов.

## 3. Что агент должен проверять сам (на любой задаче)

Кандидаты в `DataProfile.warnings` и в выбор схемы валидации. Стыковка: ml (`ml/profiling.py`, `ml/experiment.py`) и agent (подсказки LLM).

| # | Проверка | Как посчитать | Что делать, если сработала |
|---|---|---|---|
| 1 | **Сдвиг по времени** | колонка, у которой значения test лежат вне диапазона train (или сдвиг среднего > 1σ), с именем вида year/date/time/month или монотонная | валидация «последний период train» вместо KFold |
| 2 | **Дубликаты в train** | доля строк в группах полных дубликатов по признакам (`hash_pandas_object`) | при доле > 5–10% — группировать дубликаты в одном фолде (StratifiedGroupKFold / GroupKFold) |
| 3 | **Повторяющиеся объекты** | дубликаты по признакам **без** колонки времени и без колонок, меняющихся во времени; сравнить долю повторов внутри train и между train и test | GroupKFold по найденному ключу |
| 4 | **Конфликт меток** | доля дубликатов с разными таргетами | предупреждение: потолок метрики ниже; не тратить бюджет на «выжимание» |
| 5 | **Перекос таргета** (регрессия) | skew > 2, таргет ≥ 0 | гипотеза `log_target` |
| 6 | **Дисбаланс классов** | частый/редкий > 10×; класс с < 5·n_folds строк | стратификация; `class_weight`; меньше фолдов; подбор порогов под Macro F1 |
| 7 | **Новые категории в test** | значения в test, которых нет в train | кодирование с «неизвестным» значением; не падать |
| 8 | **Высокая кардинальность / редкие категории** | уникальных > 50 или значения с < 10 строками | объединять редкие в «other», target encoding внутри фолда |
| 9 | **Много пропусков** | доля NaN > 30% | флаг пропуска; не выбрасывать колонку автоматически |
| 10 | **Константы и квазиконстанты** | 1 уникальное значение или > 99.9% одно | выбросить |

⚠️ Пороги (5–10%, 1σ, skew > 2) — первые прикидки. Их надо проверить на тренировочных задачах `tasks/practice/` (ещё не созданы), чтобы не подогнать под две публичные задачи.

**Что специфично и на private не пригодится:** конкретные колонки погоды, `Year_Factor`, протоколы UNSW-NB15. В агента идут только проверки из таблицы выше.
