# Правило принятия гипотез во time-схеме (#206, #236)

Автор: roma (@Richi-Marqez) · 23.10.2026 · Стенд: `research/bench_playbook.py` (теперь сохраняет оценки по фолдам) · Разбор: `research/accept_rule_study.py` · Код агента не меняется — это исследование для владельца `agent/acceptance.py` (@n0h4ndy) и регрессии (#236, @marenkov17).

## Вопрос

На стенде агент **отклоняет честно лучшие гипотезы**: 57 из 217 проверок (график 1 питча). Сильнее всего это видно на public/regression: `objective_tweedie`, `objective_poisson`, `xgboost_log_target` честно на году 5 лучше на 11–14%, но в CV по годам 1–4 не проходят t ≥ 2. Во time-схеме фолдов всего 3, больше не сделать: в train-части 4 года. Есть ли правило, которое пропускает такие выигрыши, не снижая порог и не добавляя ложных принятий?

## Как мерили

Стенд на 12 задачах: 8 практики и public без тяжёлых multiclass и digits, плюс 4 задачи целей обучения (#237). 27 гипотез playbook (`dev` с #245), у каждой — оценки CV по фолдам и честная метрика на отложенной части.

`accept_rule_study.py` **проигрывает цикл агента**: гипотезы в порядке playbook, каждую сравнивает с *текущей лучшей* по правилу, в конце смотрит честную метрику итоговой модели против бейзлайна. Это ближе к баллу, чем принятия по парам.

Правила:
- **current** — как сейчас в `agent/acceptance.py`: скорректированная t-статистика по фолдам ≥ 2;
- **last** — для схемы `time:` гипотеза лучше на **последнем (самом позднем) периоде** и в среднем по фолдам; для остальных схем — как current;
- **last_or_t** — current или last.

## Выводы

1. **«Последний период» во time-схеме доводит до ответа выигрыш на public/regression: RMSE честно −11.7%** (`objective_poisson`). На остальных 11 задачах итог тот же, новых ошибочных шагов нет. Это половина public score: если бейзлайн организаторов линейный (R-L2-1), регрессия перестаёт давать 0.
2. **Почему это не подгонка.** Во time-схеме test лежит после train, и ближе всего к нему самый поздний период. Среднее по трём фолдам размывает его ранними годами, где связь другая. Порог t для обычных схем не меняется.
3. **Ограничение — узкая база.** Схема `time:` есть только в 3 задачах стенда (regression, sales, payments), и выигрыш дала одна. Перед включением в агента нужен харнесс «было/стало» на всех задачах и одна-две time-задачи из ночного аудита (`research/night/`).

## Предложение для `agent/acceptance.py` (@n0h4ndy)

```python
# accept(new, best, gib): после расчёта gains по фолдам
if new.validation and new.validation.startswith("time:") and gains[-1] > 0 and mean_gain > MIN_REL_GAIN * abs(best.mean_score):
    return True, f"лучше на последнем периоде ({gains[-1]:.4g}) и в среднем — time-схема"
```

Порядок фолдов во time-схеме — по возрастанию периода (`ml/validation._time_folds`), поэтому последний фолд — самый поздний период. Проверка: харнесс `--all --minutes 5` было/стало; ожидание — public/regression лучше, остальное без потерь.
