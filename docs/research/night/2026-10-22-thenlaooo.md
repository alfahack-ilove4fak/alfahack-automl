- **`semicolon_ru`**: pandas читает одну колонку `Площадь, м2;Цена;ID заказа;…`; `target` определён как «ID заказа;Цена»,

- **`cp1251_yesno`**: первое же `pd.read_csv(train, nrows=0)` (`agent/task_parser.py:67`) → `UnicodeDecodeError`, агент упал за

- **`noisy_metric_late`**: «…last year … 0.83 accuracy … main score: root mean squared error» → `find_metric_in_text` берёт
  первую подходящую (accuracy), потому что маркера «main score» нет; `_guess_task_type` (`task_parser.py:294-298`) при

## Фаза 5 — анализ и точки роста

### 5.1 Топ-10 проблем
Оценка = (вероятность встретить на скрытой задаче × потеря баллов) / сложность исправления. «Вероятность» — моя оценка, не измерение:
организаторы не дают гарантий по формату (`docs/resources/webinar-qa.md`, `[11:30]`–`[12:19]`), реальных private-задач нет.

| # | Проблема | Потеря | Исправить | Владелец |
|---|---|---|---|---|
| П1 | CSV читается только как `utf-8`, `,`, `.` | вся задача | низкая–средняя | agent, ml, evaluation, solution |
| П2 | Метрика из текста: первая подходящая, а не основная | вся задача / часть | низкая | agent (task_parser), evaluation (metrics) |
| П3 | Тип задачи выводится из метрики без проверки по данным | вся задача | низкая | agent (task_parser) |
| П4 | Нет id в test / id образца не в test | вся задача | низкая | solution, agent |
| П5 | Цель обучения не зависит от метрики (L2 всегда) | −28…38% ошибки на MAPE/pinball | низкая | ml |
| П6 | 84% «свободного» времени уходит на повторы Optuna | упущенный рост | средняя | agent (fallback), ml (tuning) |
| П7 | Optuna выдаёт параметры с AUC = 0.50000 | время, возможно качество | неизвестна | ml (tuning) |
| П8 | Харнесс без `--llm` зовёт настоящую LLM из своего процесса | ₽ и корректность замеров | низкая | evaluation |
| П9 | Нет «автомата» на LLM, которая отвечает бесполезно | токены (тай-брейк) | низкая | agent (loop) |
| П10 | AST-фильтр пропускает `…builtins.open`; песочница файлы не изолирует | риск порчи данных | низкая | agent (feature_code), runtime |

**П1. Формат CSV.** Воспроизведение:
`PYTHONPATH=. uv run python research/night/gen_tasks.py --out /tmp/night_tasks --only semicolon_ru,cp1251_yesno && PYTHONPATH=. uv run python research/night/run_tasks.py --minutes 1 --only semicolon_ru,cp1251_yesno --out $PWD/runs/night_p1`.
Числа: `semicolon_ru` — падение на 1.2 с, `target=" м2;Цена;ID заказа;…"`, ответ = копия образца (балл 0); `cp1251_yesno` — `UnicodeDecodeError`
на 10 с, ответ = образец с константой. Код выхода 0 в обоих случаях. Места: `agent/task_parser.py:38,60,67,68,74,108`,
`ml/profiling.py:19-20`, `solution.py:164-170`, `evaluation/submission.py:35`, `evaluation/harness.py`.
Предложение: один `read_table(path)` (utf-8-sig → cp1251 → latin-1; `csv.Sniffer` по первым 8 КБ для разделителя; `decimal=','` если
числа в кавычках/без точек), все вызовы — через него; **`submission.csv` писать в формате образца** (разделитель, BOM), а не жёстко `utf-8,`.

**П2. Разбор метрики.** `PYTHONPATH=. uv run python research/night/metric_phrases.py` → 9 расхождений из 47 фраз; реальных (без моих
спорных ожиданий) ≈ 7: «среднеквадратичная логарифмическая ошибка» → `None` (RMSLE по-русски не найден); «квантиль 0,75» → `None`;
«logarithmic loss» → `None`; **«Не используйте accuracy; оценка — ROC AUC» → accuracy** (отрицание ищется в окне 12 символов,
«не используйте » — 13: `evaluation/metrics.py` `_NEGATION_BEFORE`); «…accuracy only for sanity, the main score is RMSE» → accuracy
(нет маркера «main score»); «Recall@k по топ-10%» → recall; «F-beta…recall вдвое важнее precision» → recall. Полный прогон: `negation_ru` спасла
эвристика «в образце дробные значения» (`_check_needs_proba`) — не метрика, а побочный сигнал; `noisy_metric_late` и `fbeta2` — нет.
Ключевое: `agent/task_analyst.py` `reconcile` при найденной по тексту метрике **не позволяет LLM её заменить** («оставлен поиск»), даже
если LLM права; также `greater_is_better`, `task_type`, `answer_format`, `time_column`, `group_column` из ответа LLM нигде не используются
кроме `notes`. Предложение: маркеры «main score/оценка:/итоговая метрика/метрика качества», окно отрицания до 30 символов с русскими
«не используйте/не применяйте», русские названия RMSLE/logloss/«квантиль 0,75»; при расхождении поиска и LLM — сверять с данными
(тип таргета, дробность образца) и брать вариант, согласованный с данными.

**П3. Тип задачи.** `agent/task_parser.py:294-298`: `is_categorical = … or metric_name is not None`. Целевая колонка из 2769 дробных
значений + найденная «accuracy» → `multiclass, классов=2769` (`noisy_metric_late`: CV accuracy 0.0, RMSE ответа 5.61 при тривиальном 5.34
и LightGBM 1.42, пик RAM 2.3 ГБ). Предложение: float-таргет с > 20 нецелыми уникальными значениями — всегда регрессия; расхождение с метрикой
помечать и откатывать метрику к `DEFAULT_METRIC[regression]`.

**П4. Нет id.** `no_id_column`: `KeyError: 'row'` на шаге 0 (`solution.py:113`), 1.7 с, ответ = образец (price=0.0 везде).
Предложение: если `id_column` нет в test — взять id из `sample_submission` по порядку строк (длины совпали) или `range(n)`.

**П5. Цель обучения.** Нигде в `ml/`, `agent/`, `playbook.yaml`, промптах нет `objective`. Замер (5-fold, LightGBM по умолчанию,
`research/night/objective_check.py`): MAPE 0.594 → 0.430 (`objective=mape`, −28%); pinball@0.9 2.024 (агент) → 1.263 (`quantile`, α=0.9, −38%);
MAE 48.10 → 46.79 (`l1`, −2.7%; `huber` хуже — 63.3, дельта по умолчанию неудачна). В реестре метрик есть pinball, huber, MAPE, WAPE, MedAE, Poisson/Gamma/Tweedie
deviance — для каждой есть «родная» цель LightGBM. Предложение: таблица `метрика → objective(+alpha)` в `ml/experiment.py` как значение по умолчанию.

**П6. Простой бюджета.** См. фазу 4: 30 мин, 398 строк — 245 с на 20 гипотез и 1240 с на 12 повторов Optuna, выигрыш 0. На 1M строк (`big_1m_rows`)
цикл закончился на 448 из 600 с. Предложение: после 2 Optuna подряд без принятия — остановить Optuna; время отдать усреднению
по seed/блендингу уже посчитанных моделей (идея Р2).

**П7. Optuna → AUC 0.50000.** `runs/1023-055910-…/agent.log`, итерации 23–25 (запасные Optuna): `0.50000 (лучший 0.99566)`. Модель вырождается в константу;
принятие правильно отклоняет, но подбор такой модели — потерянные минуты. Причина не исследована (подозрение: `min_child_samples`/`num_leaves` из
пространства `ml/tuning.py` на малой подвыборке `rows`). Воспроизведение: `uv run python scripts/run_local.py tasks/practice/cancer_binary_auc/task.md --minutes 30 --mock-llm`.

**П8. Харнесс и LLM.** `evaluation/harness.py:145,317`: `parse_task(...)` вызывается в процессе харнесса без `LLM_MOCK=1` (для агента
`LLM_MOCK=1` ставится только в окружении подпроцесса, строка 308). В этом прогоне без `--llm` в выводе дважды: `LLM ошибка …` и прокси сообщил
о попытке соединения с `changellenge.up.railway.app`. С рабочей сетью и `.env` каждый «харнесс без LLM» тратит ₽ общего бюджета и считает
скор по `TaskSpec`, который мог выбрать Qwen, а агент в подпроцессе — другой. Все записи `docs/experiments.md` «без LLM» стоит перепроверить.

**П9. Бесполезная LLM.** `valid`-режим (LLM повторяет идеи): 199 запросов, 238 800 токенов, 9.95 ₽ до `max_iterations=200`. В `garbage`/`badjson`/`empty`:
9 запросов и 10 800 токенов впустую, т.к. счётчик сбоев (`FAILURES_TO_PAUSE`) считает только HTTP-ошибки, а не «ответ не разобрался». Предложение:
после 2 пачек подряд без единой принятой LLM-гипотезы — не звать LLM на 10 минут/до первого нового лучшего.

**П10. Песочница.** AST-фильтр: `pd.core.common.builtins.open(...)` проходит (`check_feature_code` → `None`), файл читается (`feat_cheat`). Песочница
файлы не изолирует (сказано в docstring). Низкий риск (код пишет своя LLM, на платформе нет сети), но «запрет файлов» в промпте не обеспечен.
