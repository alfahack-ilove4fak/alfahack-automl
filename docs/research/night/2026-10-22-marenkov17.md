### Находка №1. Первый фолд бейзлайна не ограничен по времени

Первый прогон харнесса шёл параллельно с pytest (4 ядра на два тяжёлых процесса). На multiclass и regression
агент за **285 с не закончил ни одного фолда бейзлайна** — в логе после «Схема валидации…» сразу
«Сторож сработал», ответ — тривиальный, балл 0.0. Логи: `runs/night/contended/*/agent.log`.

Почему: прогноз «успеем ли остальные фолды» делается **после** первого фолда (`ml/experiment.py:655`), а сам
первый фолд (до 3000 деревьев) ничем не ограничен. Запасная ступень «облегчённый бейзлайн» не запускается,
потому что первая ступень так и не вернула управление. В бою так будет на большой/широкой задаче, где один фолд
дольше ~2.5 ч, или на медленном CPU. Без нагрузки те же задачи дали 63.0 и 11.3.

### Находка №2. Запасная «Optuna» крутится по кругу

`runs/night/h5/diabetes_regression_mae/agent.log`: 107 итераций, из них ~90 — «запасное: Optuna для lightgbm»
с **одинаковым результатом 44.62295**, каждый id запускается дважды (fb-d8e7390c, fb-d8e7390c, fb-add88c85…).
Причина (`agent/fallback.py`): в params Optuna кладётся `timeout = round(доля остатка)`, он меняется каждую
итерацию → новый id и ключ, отсев повторов по `params_key` не срабатывает. Почему каждый id идёт дважды
подряд — не докопался (не успел). Подбор с тем же seed на тех же данных даёт тот же ответ. На маленькой задаче цикл
остановился только по `max_iterations=200`/концу гипотез; на большой задаче каждый такой запуск — до 600 с,
то есть **часы бюджета уходят на один и тот же подбор**.
