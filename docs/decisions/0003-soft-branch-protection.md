# 0003. Защита веток без GitHub Pro: 4 слоя

- Дата: 2026-10-20 · Кто: @thenlaooo · Статус: частично заменено 0009 (кто сливает и ревьюит)

> **Обновление 2026-10-20:** репозиторий переехал в организацию `alfahack-ilove4fak` (тариф Free) — см. [0006](0006-move-to-organization.md). Защиты веток для приватных репозиториев на Free нет и у организаций, поэтому все 4 слоя остаются; сторож теперь сверяет слияние в `main` с фиксированным ником капитана, а не с владельцем репозитория.

## Контекст
Репозиторий приватный, изначально — на личном аккаунте с тарифом Free. По документации GitHub защита веток, обязательные ревьюеры и CODEOWNERS для приватных репозиториев — только с Pro; rulesets — только Team/Enterprise. У коллабораторов личного репозитория одно право — запись (включая слияние PR), ограничить нельзя.

## Решение
1. Локальный git-хук `pre-push` (`.githooks/`, ставит `scripts/install_hooks.py`, проверяет `doctor.py`) — блокирует пуш в `main`/`dev`, удаление и force push.
2. Запреты в `.claude/settings.json` — Claude Code не выполнит такие команды.
3. `.github/workflows/guard.yml` — на каждый пуш в `main`/`dev` проверяет, что коммит пришёл из PR, а в `main` слил капитан; иначе красный CI + issue капитану. **Проверено вживую** 20.10.
4. CODEOWNERS как карта ответственности + правила в CONTRIBUTING.md.

## Альтернативы
- GitHub Pro (~$4/мес ⚠️, оплата российской картой может не пройти) или Student Developer Pack — настоящая защита. Можно включить позже, ничего не меняя в процессе.
- Организация на Free — защита только для публичных репозиториев.
- Публичный репозиторий — нельзя: решение увидят конкуренты.

## Последствия
- Обойти можно (`git push --no-verify`), но не случайно, и сторож это поймает.
- `doctor.py` проверяет, что хук стоит у каждого.
