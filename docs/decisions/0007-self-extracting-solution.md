# 0007. Самораспаковывающийся solution.py для платформы

- Дата: 2026-10-20 · Кто: @thenlaooo · Статус: принято

## Контекст
Инструкция платформы Boosters (`reference/platform_instructions.md`): в каталог задачи копируются **только корневые `.py`-файлы и `requirements.txt`**, вложенные папки теряются; запуск — `python3 solution.py task.md`; временные файлы можно писать в `/tmp`. Наш агент разложен по пакетам (`agent/`, `ml/`, `evaluation/`, `interfaces/`, `runtime/`) + `research/playbook.yaml`. Первый собранный zip (с папками) получил бы 0 баллов — обнаружено до отправки.

## Решение
`scripts/package_submission.py` собирает архив из двух файлов: `requirements.txt` и `solution.py`-загрузчик, внутри которого — код агента (ZIP в base64). При запуске загрузчик распаковывает код во временную папку, добавляет её в `sys.path` и запускает настоящий `solution.py`. Сборщик сам проверяет: ровно 2 файла, без папок, < 100 МБ. Тест `tests/smoke/test_package.py` повторяет поведение платформы (копирует только корневые файлы, запускает из каталога задачи).

## Альтернативы
- Перевести репозиторий на плоскую структуру — теряем разделение по ролям и владельцам (CODEOWNERS), конфликты в одной папке.
- «Сплющивать» модули при сборке с переписыванием импортов (`agent/loop.py` → `agent_loop.py`) — хрупко, легко сломать импорт или путь к playbook.

## Последствия
- Команда работает в структуре по папкам, платформа получает корректный архив.
- Код в zip нечитаем глазами (base64) — читаемая версия в репозитории; в шапке загрузчика — коммит сборки.
- Любые новые данные для агента (как playbook.yaml) должны лежать в упаковываемых папках и иметь расширение из `PAYLOAD_SUFFIXES`.
