# 0010. Доли времени по этапам и сторож последней минуты

- Дата: 2026-10-21 · Кто: @thenlaooo · Статус: принято

## Контекст
Балл = 0, если на платформе нет валидного `submission.csv`. Раньше «запас на финал» был одним числом (`min(15 мин, 15%)`), а при зависании или убийстве процесса защитой служила только атомарная запись ответа: сам процесс мог висеть до принудительной остановки, а ошибка агента завершала его кодом 1. LightGBM минутами не отдаёт управление питону, поэтому ни `signal.signal`, ни проверки `has_time()` между фолдами не успевают.

## Решение
1. **Доли бюджета** (`runtime/budget.py`, константы + переменные окружения): разбор + бейзлайн ≤ 20% (мягко — только предупреждение: оборванный бейзлайн хуже долгого), AutoResearch — остаток (65%), финал ≥ 10%, запас до лимита платформы ≥ 5%. `RunBudget.safety_seconds` = финал + запас (15%), поэтому цикл и фолды CV сами останавливаются вовремя. Контракт `interfaces/` не меняется.
2. **Подстройка резерва по замеру**: после сохранения бейзлайна `solution.py` замеряет финальное обучение и поднимает резерв до «запас + 3 × замер» (не выше половины бюджета).
3. **Сторож** (`runtime/watchdog.py`): отдельный поток, который по жёсткому дедлайну (за 5% бюджета до лимита платформы) или по SIGTERM/SIGINT/SIGHUP (через `signal.set_wakeup_fd`, то есть без ожидания главного потока) проверяет `submission.csv`, восстанавливает его при порче и завершает процесс через `os._exit`.
4. **`AnswerKeeper`** в `solution.py`: каждая запись ответа проверяется, невалидный ответ откатывается к последнему валидному; если не успели даже разобрать задачу — копируется `sample_submission.csv`. Любая ошибка агента заканчивается кодом 0.

## Альтернативы
- Только `signal.signal` в главном потоке — обработчик выполняется после возврата из C-кода (минуты), не годится.
- Маска сигналов + `sigtimedwait` — наследуется дочерними процессами (песочница) и не работает на Windows, где часть команды запускает агента.
- Обрывать бейзлайн по доле 20% — при таймауте остаётся тривиальный ответ; дешевле предупредить.

## Последствия
- Платформа получает валидный файл и код 0 при любом зависании, сигнале или ошибке; на 3 часах AutoResearch заканчивается за 27 мин до конца, сторож — за 9 мин.
- Все, кто пишет `submission.csv`, обязаны идти через `AnswerKeeper.write` / `write_submission_atomic`.
- Цикл (`agent/`) и эксперименты (`ml/`) по-прежнему проверяют `budget.has_time()` сами — сторож лишь страховка, а не планировщик.
