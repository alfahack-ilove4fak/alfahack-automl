# Роль: QA / MLOps (`qa`)

**Ты отвечаешь за то, чтобы агент работал всегда и мы знали, насколько он хорош** — тесты, CI, локальный лидерборд (харнесс), проверка перед сабмитом, репетиции «как на платформе». Ещё ты помогаешь всем с окружением (doctor).
**Твоя зона:** `evaluation/`, `scripts/`, `tests/`, `.github/workflows/`. **Ревьюит тебя:** капитан. **Ты ревьюишь:** капитана и релизы `dev → main`.
**Материалы:** [docs/resources/qa.md](../resources/qa.md) · **Модуль:** [evaluation/CLAUDE.md](../../evaluation/CLAUDE.md)

## 3.1 Установка (сверх [docs/install.md](../install.md))

Ядра (`uv sync`) достаточно; ruff и pytest уже в группе `dev`.
- Для тестов тяжёлых моделей: `uv sync --group full` (⚠️ лучше в Codespaces).
- **Docker** — не обязателен (у нас нет 32 ГБ), но полезен для эмуляции лимитов: Windows/macOS — Docker Desktop (https://docs.docker.com/get-docker/), Linux — `sudo apt install docker.io`.
- **GitHub Codespaces** — для 3-часовых репетиций: `Code → Codespaces → ⋯ → New with options → 4-core / 16 GB`.

**Проверка:** `uv run python scripts/doctor.py --role qa` → `✅ доступ к GitHub Actions` (Docker — ⚠️ допустимо).

## 3.2 Git в твоей роли

Общий гайд — [docs/git-guide.md](../git-guide.md). Для тебя важно:
- Ветки: `qa/<задача>` — например `qa/harness`, `qa/pre-submit`.
- Ты ревьюишь **релизы** `dev → main`: перед одобрением — CI зелёный, харнесс не хуже прошлого релиза.
- CI — твоя зона: красный CI в чужом PR — помоги понять причину (`gh run view <id> --log-failed`).
- Workflow `.github/workflows/*.yml` проверяй в своей ветке: пуш ветки запускает `ci`; `run-agent` — вручную (`gh workflow run run-agent.yml --ref <ветка>`).
- Помни про бюджет Actions: 2000 мин/мес на приватный репозиторий — тяжёлое только вручную.

## 3.3 Рабочие инструменты по кейсу

| Инструмент | Зачем тебе |
|---|---|
| pytest | все тесты: контракты, юнит, дымовые прогоны агента |
| ruff | стиль и типичные ошибки (в CI и в хуке Claude) |
| GitHub Actions (`ci`, `guard`, `run-agent`) | проверка каждого PR, сторож веток, прогон агента в облаке |
| `scripts/doctor.py` | проверка рабочих мест команды — ты его владелец |
| `evaluation/metrics.py`, `submission.py` | реестр метрик и валидатор сабмита |
| psutil, `resource` (Linux) | замер и ограничение памяти в репетициях |
| Docker / Codespaces | эмуляция платформы: лимиты CPU/RAM, чистое окружение |
| `scripts/package_submission.py` | сборка zip для платформы |

### L1 — базовые

#### Q-L1-1 · Харнесс — локальный лидерборд · CP3

*Зачем:* Платформа даёт 3 сабмита в день; всё остальное мы должны оценивать сами.

**Готово, когда:**
- [ ] Одна команда даёт таблицу баллов по всем задачам.

**🔗 Стыковка:** research — тренировочные задачи (R-L1-3); все — пользуются харнессом.

#### Q-L1-2 · Проверка перед сабмитом (scripts/pre_submit.py) · CP2

*Зачем:* Ошибка формата = потерянный сабмит из трёх в день.

1. Собрать zip → распаковать во временную папку → запустить оттуда на копиях задач с лимитом времени.
2. Проверить сабмит валидатором; проверить импорты (только requirements.txt).

**Готово, когда:**
- [ ] Скрипт используется в /submit-check, капитан сабмитит только после него.

**🔗 Стыковка:** captain — каждый вечер перед сабмитом.

#### Q-L1-3 · Расширить реестр метрик · CP3

*Зачем:* Скрытые задачи могут прийти с метрикой, которой нет у нас.

1. Добавить: RMSLE-варианты, weighted/multiclass ROC-AUC, Gini, precision/recall, MAPE-варианты — что разумно.
2. Русские и английские формулировки в aliases; тесты на поиск в тексте.

**Готово, когда:**
- [ ] Тесты на ≥ 20 формулировок метрик зелёные.

**🔗 Стыковка:** agent — разбор задачи использует реестр.

### L2 — основные

#### Q-L2-1 · Набор тестов на устойчивость · CP4

*Зачем:* Скрытая задача может быть «кривой» — агент не должен падать.

1. Варианты: нет sample_submission, лишние файлы, CRLF, пустые колонки, unicode в именах, target с пропусками, 1 объект в классе.
2. Каждый — дымовой тест, агент обязан сдать валидный ответ.

**Готово, когда:**
- [ ] ≥ 8 тестов устойчивости в CI.

**🔗 Стыковка:** owners модулей — чинят найденное.

#### Q-L2-2 · Генеральная репетиция — 3 часа · CP4

*Зачем:* Убедиться, что агент выдерживает полный бюджет времени и памяти.

1. Codespaces 4 ядра / 16 ГБ (см. docs/decisions/0005); прогон обеих задач по 180 минут.
2. Снять пиковую память и время этапов, отчёт в docs/experiments.md.

**Готово, когда:**
- [ ] Полный прогон без падений, отчёт команде.

**🔗 Стыковка:** captain — доли бюджета; ml — память.
