# Роль: ML-pipeline инженер (`ml`)

**Ты делаешь «руки» агента**: как гипотеза превращается в честный эксперимент — признаки, модель, кросс-валидация, финальное обучение. От тебя зависит, будет ли оценка правдивой и уложится ли агент во время.
**Твоя зона:** `ml/`. **Ревьюит тебя:** research. **Ты ревьюишь:** agent и research.
**Материалы:** [docs/resources/ml.md](../resources/ml.md) · **Модуль:** [ml/CLAUDE.md](../../ml/CLAUDE.md)

## 3.1 Установка (сверх [docs/install.md](../install.md))

Тебе нужна тяжёлая группа зависимостей (CatBoost, XGBoost, AutoGluon, torch-CPU):
```
uv sync --group full
```
→ Должно появиться: `Installed N packages` (⚠️ ~1.5 ГБ; на медленном интернете — делай в GitHub Codespaces: `Code → Codespaces → Create codespace on dev`, там `uv sync --group full` за пару минут).
**Проверка:** `uv run python scripts/doctor.py --role ml` → `✅ библиотеки роли ml`.
Системная библиотека для LightGBM/XGBoost (VC runtime на Windows, `libomp` на macOS) — общий шаг [docs/install.md, 3а](../install.md#3а-системная-библиотека-для-lightgbm-одна-команда).

## 3.2 Git в твоей роли

Общий гайд — [docs/git-guide.md](../git-guide.md). Для тебя важно:
- Ветки: `ml/<задача>` — например `ml/catboost`, `ml/validation-schemes`.
- Новый ключ `Hypothesis.params` = изменение договорённости с agent: docstring `ml/experiment.py` + пример в playbook (через research) + сообщение agent-инженеру. Перед PR — `/sync-check`.
- Ты ревьюишь agent и research: на ревью ищи прежде всего утечки и «улучшения в пределах шума» (git-guide, раздел 9).
- Экспериментируешь в ноутбуке — переноси в код через PR, ноутбук с выводом не коммить.

## 3.3 Рабочие инструменты по кейсу

| Инструмент | Зачем тебе |
|---|---|
| LightGBM 4.6 | основная модель агента — быстрая, хорошо работает с пропусками и категориями |
| CatBoost 1.2.8 | сильная на категориальных признаках, мало настройки |
| XGBoost 2.1.4 | ещё один бустинг для разнообразия ансамбля |
| scikit-learn 1.5.2 | фолды (KFold, StratifiedKFold, GroupKFold), метрики, линейные модели, препроцессинг |
| Optuna 4.2.1 | подбор гиперпараметров с таймаутом |
| AutoGluon 1.3.1 / LightAutoML 0.4.2 / FLAML 2.3.6 | готовые AutoML — как гипотеза «под ключ» или источник идей; ⚠️ тяжёлые по памяти и времени |
| category-encoders, feature-engine | кодирование категорий и преобразования признаков |
| pandas 2.2, numpy 1.26, polars | данные |
| `evaluation/metrics.py` | реестр метрик — используй только его |
| `runtime/budget.py` | сколько осталось времени и памяти |

### L1 — базовые

#### M-L1-1 · CatBoost в run_experiment · CP3

*Зачем:* CatBoost обычно сильнее на категориальных признаках — нужен агенту как вариант.

1. `uv sync --group full`. Ключ `params.model: catboost` в experiment.py (+ docstring).
2. Категории — через встроенную обработку CatBoost; ранняя остановка на валидации фолда.
3. Тест на маленьких данных; пример гипотезы — передать research для playbook.

**Готово, когда:**
- [ ] Гипотеза с CatBoost проходит на обеих публичных задачах, тест зелёный.

**🔗 Стыковка:** agent и research — новый ключ params (13:00).

#### M-L1-2 · Ещё модели для разнообразия (XGBoost, линейная) · CP3

*Зачем:* Разные модели ошибаются по-разному — это основа для ансамблей.

1. `model: xgboost` и `model: linear` (Ridge/LogisticRegression с масштабированием и one-hot).
2. Тесты, примеры в playbook.

**Готово, когда:**
- [ ] Три типа моделей доступны через params.

#### M-L1-3 · Защита по времени и памяти внутри эксперимента · CP3

*Зачем:* Скрытая задача может быть в 10 раз больше публичной.

1. Оценка памяти матрицы до обучения; при нехватке — подвыборка для CV с записью в лог.
2. Прогноз длительности по первому фолду; если не успеваем — меньше фолдов или стоп.

**Готово, когда:**
- [ ] Тест на «большой» синтетике (1–2 млн строк, мало признаков) не падает и укладывается в бюджет.

**🔗 Стыковка:** captain — доли бюджета (C-L2-2).

### L2 — основные

#### M-L2-1 · Схемы валидации через params · CP4

*Зачем:* В регрессии одно здание встречается в разные годы — случайные фолды завышают оценку.

1. `params.validation`: kfold | stratified | group(колонка) | time(колонка).
2. Вместе с research проверить, какая схема лучше предсказывает public.

**Готово, когда:**
- [ ] Схемы доступны, решение по умолчанию записано в docs/decisions/.

**🔗 Стыковка:** research — исследование валидации (R-L2-1).

#### M-L2-2 · Библиотека преобразований признаков · CP4

*Зачем:* Агенту нужны готовые «кубики», которые он комбинирует гипотезами.

1. `params.feature_ops`: индикаторы пропусков, частотное кодирование, target encoding внутри фолдов, разности/отношения пар признаков.
2. Каждая операция — функция + тест на утечку (обучается только на train-части).

**Готово, когда:**
- [ ] ≥ 4 операции, описаны в docstring, есть примеры в playbook.

#### M-L2-3 · Подбор гиперпараметров Optuna с лимитом времени · CP4

*Зачем:* Дешёвый прирост качества, если уложиться во время.

1. `kind: hyperparams` с `params.optuna: {trials, timeout}`; поиск на подвыборке/меньшем числе фолдов.
2. Сравнить с ручными гипотезами по времени и качеству.

**Готово, когда:**
- [ ] Гипотеза работает с жёстким таймаутом, результат в журнале.

### L3 — на победу

#### M-L3-1 · Ансамбль лучших моделей по OOF · CP4

*Зачем:* Смесь разных моделей почти всегда лучше одной.

1. Сохранять OOF и test-предсказания экспериментов (пути в ExperimentResult).
2. `kind: ensemble`: взвешенное среднее топ-k, веса — по OOF.
3. Финал — ансамбль, если он лучше лучшей модели с учётом шума.

**Готово, когда:**
- [ ] На харнессе ансамбль не хуже лучшей одиночной модели ни на одной задаче.

**🔗 Стыковка:** captain — финальное обучение в solution.py.

#### M-L3-2 · Пороги и веса классов под Macro F1 · CP4

*Зачем:* Macro F1 сильно зависит от редких классов.

1. Подбор множителей вероятностей классов на OOF (не на тесте!).
2. Проверка на шум — сравнение по фолдам.

**Готово, когда:**
- [ ] Улучшение Macro F1 на OOF больше шума; записано в журнал.

## 3.5 Claude Code в твоей роли

- **Скилл** `ml-pipeline` подключается сам в `ml/`: рецепт «добавить вариант в run_experiment», принципы без утечек.
- **Команды:** `/next-task`, `/sync-check`, `/pre-pr`, `/explain target encoding`.
- **Сабагенты:** `ml-mentor` — «почему случайные фолды завышают оценку на регрессии?»; `test-writer` — тест на утечку; `code-reviewer` — перед PR.
- **context7** — параметры LightGBM/CatBoost/Optuna нужных версий: «use context7, early stopping в catboost 1.2».
- **Опционально:** `pyright-lsp`, `code-simplifier` — см. SETUP_CLAUDE.md.

Примеры запросов:
> «Режим готового решения: добавь params.model = catboost по рецепту из скилла ml-pipeline, с тестом»
> «Проверь мой target encoding на утечку»
> «Оцени, сколько памяти займёт матрица 2 млн × 60 float32 и уложимся ли в 14 ГБ»
