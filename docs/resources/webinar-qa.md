# Вебинар организаторов (Q&A по кейсу) — разбор для команды

**Источник:** запись вебинара ~35 мин; эксперты Альфа-Банка — **Данила** и **Андрей** (авторы кейса, команда автоматизации ML; не путать с нашим Данилом). Полная расшифровка с метками времени — [`reference/webinar_transcript.md`](../../reference/webinar_transcript.md). Расшифровка автоматическая: если решение зависит от одной фразы, сверь её с видео по метке `[мм:сс]`.
**Что это за документ:** общий для всех. Что из этого делать лично тебе — в `docs/plan/2026-10-22/<твоё_имя>.md`, раздел «Из вебинара». Дополняет [`reference/organizer_chat_faq.md`](../../reference/organizer_chat_faq.md) (ответы из чата), а не заменяет его.

## 1. Главное за одну минуту

1. **Детерминированный агент пройдёт первый этап, но проиграет дальше.** Эксперты трижды (`[06:10]`, `[15:29]`, `[25:38]`, `[32:00]`) сказали: после отбора задачи станут «сильно сложнее», парсеры и жёсткая логика перестанут работать, «такие решения не имеет смысла делать». Просили делать агента, который отталкивается от текста `task.md` и свободно принимает решения. Наш первый сабмит (public 17.4595) — на одном playbook, без LLM: для этапа 1 это допустимо, но рассчитывать на это в финале нельзя.
2. **Граница «агент / не агент»:** LLM должна осмысленно выбирать действия, смотреть на результат и использовать инструменты дальше. Не агент — детерминированный алгоритм + имитация нагрузки на LLM параллельным процессом (`[06:10]`). Топ-решения организаторы **посмотрят вручную** (`[07:43]`, `[23:42]`, `[24:01]`, `[24:42]`).
3. **Скрытые задачи:** только табличные (не будет NLP, CV, рекомендательных систем), но **никаких гарантий** по формату: несколько таргетов, ранжирование, вероятности, дисбаланс, новые категории в test, высокая кардинальность — «может быть как в жизни» (`[11:30]`–`[14:46]`). Всё нужное агент должен вывести из `task.md`.
4. **Схему валидации агент выбирает сам**, подсказок не будет (`[14:15]`). Корректность валидации организаторы **не проверяют** — только качество итоговых предсказаний (`[17:25]`).
5. **Ничья по баллу решается токенами, потом временем:** меньше токенов Qwen — лучше, быстрее — лучше (`[23:17]`, `[25:04]`). Отображаемый балл округляется, внутри точность ~10 знаков.
6. **Одна попытка на скрытую задачу** (`[24:27]`). Упала одна задача — за неё минимум, за вторую баллы сохраняются (`[25:16]`). Перезапуск только при ошибке платформы.

## 3. Что это значит для нашего проекта (выводы, решения — за командой)

1. **LLM должна реально участвовать.** Сейчас её вклад в сабмите нулевой, потому что Qwen отвечает `Connection error`. Починка (задача Артёма и капитана) — не «хорошо бы», а условие допуска во второй этап и защита от ручного просмотра топа. Playbook остаётся надёжным фолбэком, но в логе прогона должны быть видны решения LLM, которые влияют на итог.
2. **Не зашивать формат public-задач.** Проверить код на места, где мы предполагаем конкретную структуру (`task.md`, имена колонок, один таргет, один столбец ответа). Гарантий нет, а вероятности, мультитаргет и ранжирование возможны.
3. **Выбор схемы валидации — главное для ML-части** (#150): организаторы подтвердили, что подсказок не будет, а KFold на данных со временем обманывает.
4. **Токены и время — тай-брейки.** Не гнаться за «ещё одним вызовом LLM» без ощутимого выигрыша; в харнессе стоит логировать токены и время каждого прогона.
5. **Public-лучший уходит в private.** Каждый из 3 сабмитов в день важен: не отправлять экспериментальный без `pre_submit`; хуже public — не попадёт в private даже если надёжнее на скрытых задачах (пока ручной выбор не разрешили).
6. **Тест на «неудобные» задачи.** Харнессу и практическим задачам не хватает: мультитаргет, вероятностный ответ, ранжирование, редкие классы, новые категории в test, даты строкой, расхождение словаря данных с `train`.
