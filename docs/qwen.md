# Qwen: как пользоваться LLM всей командой

**Зачем это важно.** На вебинаре организаторы прямо сказали: агент, где LLM ничего не решает, проиграет во втором этапе, а топ-решения посмотрят вручную ([webinar-qa](resources/webinar-qa.md)). При равном балле выигрывает тот, кто потратил **меньше токенов**, потом — кто быстрее. Значит, Qwen должна реально работать у каждого из нас, а расход — быть виден.

## Факты (проверено 22.10)

| Что | Значение |
|---|---|
| Сервер | прокси LiteLLM, OpenAI-совместимый: `OPENAI_BASE_URL=https://changellenge.up.railway.app/v1` |
| Модель | `OPENAI_MODEL=qwen/qwen3.8-27b` — reasoning-модель: скрытые рассуждения тратят тот же `max_tokens` |
| Ключ | один на команду, у капитана; в репозитории — секрет `OPENAI_API_KEY` для GitHub Actions |
| Бюджет разработки | **600 ₽ в сутки на всю команду**, сброс в **03:00 МСК** (00:00 UTC). Остаток — `GET /key/info` |
| На платформе | ограничений по ₽ и токенам нет (только время) |
| Цена | прокси сам возвращает стоимость запроса (`usage.cost`); короткий запрос ≈ 0.01–0.02 ₽ |
| Скорость | короткий ответ 2–7 с; запрос гипотез с `reasoning_effort=low` 6–9 с (без него 15–35 с) |

## Путь 1. В облаке — без ключа на ноутбуке (для всех)
GitHub → **Actions → qwen → Run workflow**:

| Режим | Что делает | Минуты Actions |
|---|---|---|
| `check` | связь с Qwen + остаток бюджета | ~2 |
| `run` | агент с Qwen на задаче (`task`: путь к `task.md` или `all`) + сводка: запросы, гипотезы от LLM, ₽ | minutes × задачи + 3 |
| `compare` | харнесс «без LLM против Qwen» — помогает ли LLM **честно** | 2 × minutes × задачи + 3 |

- Одновременно идёт **один** такой запуск (общий бюджет), остальные ждут в очереди.
- Если в бюджете меньше `min_rub` (по умолчанию 50 ₽) — запуск останавливается до траты.
- Итог — на странице запуска (Summary), логи агента и журнал вызовов LLM — в Artifacts.
- Раннер слабее платформы (2 CPU / 7 ГБ). Минуты Actions общие (2000/мес) — не ставьте часы.

## Путь 2. Локально (если ключ есть в твоём `.env`)
```
uv run python scripts/qwen.py check                     # связь, ✅/❌ и подсказка, что чинить
uv run python scripts/qwen.py budget                    # потрачено / осталось / когда сброс
uv run python scripts/qwen.py run tasks/public/multiclass/task.md --minutes 8
uv run python scripts/qwen.py compare --minutes 5       # без LLM против Qwen на всех задачах харнесса
```
`scripts/run_local.py` и харнесс сами подхватывают `.env` (переменные, уже заданные в оболочке, важнее).
Ключ получают только у капитана лично — **не в чат**. В `.env`: без кавычек, без пробелов, без `Bearer`.

## Что видно после прогона
- В `agent.log` — `Итерация N: <id> — <что> [llm|playbook]`: откуда гипотеза.
- В конце цикла — `LLM итог: N запросов, ошибки, токены (вход/выход/рассуждения), секунды ожидания, ₽`.
- `llm_calls.jsonl` рядом с логом — каждый вызов: зачем (`hypotheses`, `critic`, `reflect`), токены, время, цена, **ответ модели** (4000 символов). Это и есть «решения LLM» — для питча и ручной проверки организаторов.

## Правила расхода (общие 600 ₽)
1. Сначала — без LLM (`--mock-llm`), пока не уверен, что код работает. Qwen — для проверки именно LLM-части.
2. `check` и `budget` — почти бесплатно; `compare` на всех задачах — самый дорогой, договаривайтесь в чате.
3. Остаток < 100 ₽ — пишем в чат, до сброса в 03:00 МСК гоняем только без LLM.
4. Меньше токенов = лучше на тай-брейке: не добавляем вызовы LLM без выигрыша в харнессе.

## Если не работает
| Симптом | Что проверить |
|---|---|
| `Connection error ← Server disconnected without sending a response` через 10–17 с | **сервер организаторов перегружен** (22.10 днём падало до 5 запросов из 6). Клиент сам повторяет запрос (паузы 2, 5, 10 с) и после 3 сбоев подряд делает паузу 2 мин, а не выключает LLM. Если массово — писать организаторам (текст ниже) |
| `Connection error` с другой причиной | `scripts/qwen.py check` покажет цепочку целиком (DNS / TCP / TLS); URL с `https://` и `/v1` |
| `401` | ключ: без кавычек, пробелов и `Bearer`; не перекрыт ли переменной в оболочке |
| пустой ответ, `упёрлась в лимит` | рассуждения съели `max_tokens` — увеличить `LLM_REASONING_TOKENS` |
| `budget exceeded` / отказ | дневные 600 ₽ кончились — ждать 03:00 МСК |
| `LLM выключена` | `LLM_MOCK=1` в `.env` или нет ключа |

**Причина вчерашнего `Connection error` найдена (22.10):** сервер модели под нагрузкой обрывает соединение, не ответив («Server disconnected without sending a response»), если запрос ждёт дольше ~10–17 с. Прокси при этом жив (`/v1/models` → 200). Это не наш ключ и не наш код. Что сделано в клиенте:
- повторы при обрыве/таймауте/429/5xx (паузы 2, 5, 10 с) — в пределах отведённого на LLM времени;
- после 3 сбоев подряд — пауза `LLM_COOLDOWN_SEC` (120 с), потом снова пробуем (раньше LLM выключалась до конца прогона);
- **короткие рассуждения:** `reasoning_effort=low` (через `extra_body`) — рассуждений ≈ в 2.5 раза меньше: запрос гипотез 0.33 ₽ вместо 1.02 ₽, 6–9 с вместо 30+ с — и реже попадаем под обрыв. Выключить: `LLM_REASONING_EFFORT=` (пусто). Варианты `enable_thinking`, `/no_think`, системная просьба «думай кратко» — не работают.

**Второй вчерашний симптом** — «упёрлась в лимит 3800 токенов, ответ пустой»: без `reasoning_effort=low` Qwen рассуждала дольше лимита и не успевала ответить — 1 ₽ за пустоту.
