Помоги участнику выбрать следующую задачу.

1. Определи роль (`gh api user --jq .login` → `docs/team.md`).
2. Посмотри состояние: его открытые issue и PR (`gh issue list --assignee @me`, `gh pr list --author @me`), текущая ветка, ближайший чек-поинт и дата (`docs/checkpoints.md`; сегодня — посмотри дату в окружении).
3. Открой чек-лист роли `docs/roles/<роль>.md` и найди первую незакрытую задачу самого низкого уровня (L0 → L1 → L2 → L3), с учётом ближайшего чек-поинта. Если есть незавершённая начатая задача — сначала она.
4. Ответь коротко:
   - **Задача** (номер issue, если есть) и зачем она;
   - **Шаги** (3–6 штук);
   - **Готово, когда** — критерий;
   - **Стыковка** — с кем, когда, что передаёте (если есть);
   - **Ветка**: `git switch dev && git pull && git switch -c <роль>/<задача>`.
5. Спроси: «Режим — подсказка или готовое решение?» и начинай.

Если участник явно занят чем-то другим (`$ARGUMENTS` или по контексту) — помоги с этим, а не тяни к чек-листу.
