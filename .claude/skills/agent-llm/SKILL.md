# Навык: LLM-агент для AutoResearch

Пакет роли: `docs/roles/agent.md` · материалы: `docs/resources/agent.md` · модуль: `agent/CLAUDE.md`.

## Рецепт: гипотезы от LLM
1. Вход промпта: `TaskSpec` (тип, метрика, направление), сжатый `DataProfile` (размеры, типы, пропуски, дисбаланс, предупреждения), история `[(Hypothesis, ExperimentResult)]` — **только итоги**, не сырые данные.
2. Явно перечисли допустимые `kind` и ключи `params` (из docstring `ml/experiment.py`) и попроси ответ строго JSON-списком.
3. Разбор: `LLMClient.chat_json` → валидация через `Hypothesis.model_validate` → отбросить невалидные и повторы уже проверенных (`id`/`params`).
4. Пусто или ошибка → `propose_hypotheses` из playbook. Цикл не должен останавливаться из-за LLM.
5. Тест: monkeypatch `LLMClient.chat` возвращает (а) хороший JSON, (б) JSON в ```json, (в) мусор, (г) None — во всех случаях цикл живёт.

## Принципы
- Маленькая модель (Qwen ~27B): короткие промпты, один шаг за запрос, примеры формата (few-shot из playbook), `temperature` 0.2–0.5.
- Сначала «дешёвые» гипотезы (гиперпараметры, веса классов), потом дорогие (новые признаки кодом, ансамбли).
- Защита от «взлома метрики» (кейс прямо про это): гипотеза принимается только по честной CV и с порогом шума `min_delta`.
- Бюджет: кэш (`LLM_CACHE_DIR`), лимит (`LLM_RUB_LIMIT`), отладка — `LLM_MOCK=1`. 600 ₽/день — на всю команду.
