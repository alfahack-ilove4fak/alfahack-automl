# Тренировочные «скрытые» задачи

Зачем: на private будут две задачи с неизвестными данными и метрикой. Эти задачи проверяют, что агент
не подогнан под две публичные. Владелец — research, генератор — `research/make_practice_tasks.py`
(детерминированный, без интернета).

```
uv run python research/make_practice_tasks.py                 # пересоздать все
uv run python scripts/run_local.py --all --minutes 5 --mock-llm
```

| Задача | Метрика | Строк train / test | Что проверяет |
|---|---|---|---|
| `cancer_binary_auc` | ROC-AUC ↑ | 398 / 171 | маленькие данные; ответ — **вероятность**, а не класс |
| `diabetes_regression_mae` | MAE ↓ | 309 / 133 | очень маленькая регрессия, другая метрика; категория `sex` |
| `digits_multiclass_accuracy` | accuracy ↑ | 1 257 / 540 | классы записаны **числами** 0–9 — не перепутать с регрессией |
| `sales_regression_dates_rmsle` | RMSLE ↓ | 30 000 / 6 000 | дата строкой, 150 магазинов (высокая кардинальность), пропуски, test **позже** train, скошенный таргет ≥ 0 |
| `network_binary_logloss_crooked` | LogLoss ↓ | 19 600 / 8 400 | «кривой» `task.md`: по-английски, неверные пути, файлы во вложенной папке, нет `sample_submission` и словаря, id — `flow_id`, **ловушка**: в тексте сначала упомянута accuracy («we do NOT use it») |

Источники: `sklearn.datasets` (breast_cancer, diabetes, digits), синтетика (продажи) и переделка публичной
`multiclass` в бинарную «атака / норма».

## Ответы

Ответы лежат **отдельно от задач**: `_answers/<задача>.csv` (столбцы — id и таргет, как в сабмите), метрики —
`_answers/manifest.json`. `scripts/run_local.py` копирует агенту только папку задачи, как платформа, поэтому
агент ответов не видит. Балл по формуле организаторов считает харнесс QA (`evaluation/`).

## Правила

- Задачи не подгоняем под агента: если агент падает или выбирает не ту метрику — чиним агента.
- Новая задача — новая функция с `@task(...)` в генераторе и строка в таблице выше.
