# interfaces/ — контракты между модулями (владелец: капитан, меняется только по процессу)

## Что здесь
`schemas.py` — модели данных (pydantic, `extra="forbid"`) · `protocols.py` — сигнатуры функций и где они живут · `stubs.py` — заглушки для параллельной работы · `CHANGELOG.md` — история версий.

## Правило изменения (жёсткое)
1. Сначала `/sync-check`: кто использует поле/функцию (`grep` по репозиторию), что сломается.
2. Сообщение в чат владельцам затронутых модулей.
3. Отдельный PR **только** с изменением контракта: `CONTRACT_VERSION` повышен (patch — новое необязательное поле; minor — новый контракт; major — переименование/удаление), строка в `CHANGELOG.md`, обновлены `stubs.py` и `tests/contracts`.
4. Два одобрения от коллег (затронутых владельцев зови ревьюерами); сливает бот; CI проверяет версию и `CHANGELOG.md`. Major — только на синке.

Если участник просит «быстро добавить поле» — не делай молча: объясни процесс и предложи подготовить PR по нему.
