## Что здесь
| Файл | Роль |
|---|---|
| `task_parser.py` | `task.md` + файлы → `TaskSpec`. Детерминированная часть работает без LLM — не ломать! Роль файла — по словам имени (`file_role`: `data_train`, `TRAIN.CSV`, `learn`/`holdout`, `.csv.gz`/`.zip`/`.tsv`), ближайший и каноничный — первым |
| `csv_dialect.py` | файлы задачи «как в жизни» (cp1251, «;», десятичная запятая) → обычная копия CSV во временной папке (также сжатые `.gz/.zip/.bz2/.xz`, `.tsv/.txt` и десятичная запятая в кавычках «"10,5"» при разделителе «,»); `find_task_files` отдаёт пути к копиям, поэтому остальные модули читают как обычно (#238) |
| `task_analyst.py` | LLM-аналитик задачи: один запрос после шага 0 (`solution.py` сначала пишет тривиальный ответ по разбору без LLM — `parse_task(use_analyst=False)`, #239), Qwen читает `task.md` и колонки; ответ сверяется с данными: LLM заменяет только угаданные поля (target/id/метрику, если словарь не нашёл её в тексте и она есть в реестре; в лог — «метрика от аналитика: X»), остальное — в `notes`; `AGENT_ANALYST_APPLY=0` — только заполнять пустое, замены угаданного — в `notes` (#276). `AGENT_LLM_TASK=0` выключает |
| `llm_client.py` | Qwen через OpenAI-совместимый API: кэш на диск, учёт ₽, `available()` = False без ключа; по остатку бюджета (`seconds_left`) ждёт не дольше четверти оставшегося времени, при < 4 мин не зовёт LLM (ответу нужна минута: запрос до 64 с плюс повторы); весь запрос с повторами — не дольше `LLM_MAX_CALL_SEC` (90 с), срок проверяется и внутри потока, 3 запроса подряд по таймауту → пауза 10 мин (`LLM_TIMEOUT_COOLDOWN_SEC`), потом снова (#239) |
| `hypotheses.py` | `propose_hypotheses(spec, profile, history, k, budget)`: сначала LLM (если доступна и хватает времени), недостающие — из `research/playbook.yaml`; повторы id/params отсекаются |
| `llm_hypotheses.py` | ответ LLM → проверенные `Hypothesis`: схема, допустимые kind и ключи params, без повторов |
| `prompting.py` | сборка промптов из `agent/prompts/*.md` (string.Template, `$плейсхолдеры`); нет файла → `None` → playbook |
| `feature_code.py` | код признаков от LLM: промпт `prompts/features.md`, разбор ответа, проверка кода до песочницы (AST); `apply_feature_code(code, df)` — запуск в песочнице, возвращает df + новые числовые колонки или причину; `propose_feature_hypothesis` — запрос кода у LLM, цикл зовёт после первой пачки ≤ `MAX_FEATURE_TRIES` раз; по умолчанию выключено, `AGENT_FEATURE_CODE=1` включает (#276); в `ml/experiment.with_feature_code` код применяется до фолдов |
| `memory.py` | память цикла: решение по каждой гипотезе и последние выводы LLM после неудачных пачек |
| `critic.py` | критик по правилам: пустые для задачи гипотезы, недопустимые значения, цена по времени → пропуск (`SKIPPED`) до запуска |
| `llm_critic.py` | LLM-критик: одна проверка пачки LLM-гипотез до запуска (утечка, подгонка, метрика, повтор, цена); `AGENT_LLM_CRITIC=1`, при сбое пропускает всё |
| `fallback.py` | запасные направления (#200), когда playbook и LLM пусты: модели и ансамбли (порядок danil по стенду), Optuna, «почти прошедшие», playbook поверх лучшего, усреднение seed, Optuna других моделей и глубже; цикл берёт их порциями по `FALLBACK_CHUNK` (между порциями ход LLM), после нового лучшего строит заново. `AGENT_FALLBACK=0` выключает |
| `loop.py` | цикл AutoResearch: очередь гипотез (по 3 за запрос к LLM) → `ml.run_experiment` → `acceptance.accept`; у гипотез LLM свой порог — по умолчанию как у playbook (t ≥ 2, time-схема ≥ 1%), строже через `AGENT_LLM_T_MIN`, `AGENT_LLM_TIME_GAIN` (#276); `AGENT_TIME_LAST_PERIOD=0` выключает правило «лучше на последнем периоде» во time-схеме — нужно t ≥ 2 (#295) |

## Контракты
- Создаёшь: `TaskSpec`, `Hypothesis`. Читаешь: `DataProfile`, `ExperimentResult`, `RunBudget`.
- `Hypothesis.params` должен быть понятен `ml/experiment.py` — список ключей в его docstring. Новый ключ → договорись с ML-инженером (стыковка ежедневно в 13:00).

## Правила модуля
- **LLM — улучшение, а не опора.** Любой путь кода должен работать при `LLM_MOCK=1`. Ответ LLM всегда валидируй (pydantic), мусор → пропускаем гипотезу.
- Код, который пишет LLM, исполняется только в песочнице (отдельный процесс + таймаут, как `run_python` в `reference/baseline.py`), никогда через `exec` в процессе агента.
- Промпты — в файлах `agent/prompts/*.md`, не строками в коде. Каждый промпт содержит профиль данных и историю экспериментов, но не сырые данные.
- Бюджет: 600 ₽/день на всю команду. Отлаживай с `LLM_CACHE_DIR` и `LLM_RUB_LIMIT` из `.env`.

## Стыкуется с
